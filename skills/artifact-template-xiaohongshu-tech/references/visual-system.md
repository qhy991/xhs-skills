# 深绿科技图文：视觉系统

本规范提炼自已完成的九页苹果 GPU 图文及其 Canvas renderer、总览图和全尺寸成图。延续 3:4 竖版、深绿／米白／荧光绿、强标题与短卡片的科技杂志感；主题词、案例、图形和主视觉按新主题替换。

目录：尺寸与颜色、字体与文字、版式节奏、封面主视觉、渲染与检查、交付。

## 1. 尺寸与固定网格

| 参数 | 值 |
|---|---|
| 成图尺寸 | 1440 × 1920 px，3:4 |
| 主文字左右边距 | 96 px |
| 主内容宽度 | 1248 px |
| 顶部系列标识 | 左侧 x=96；图标 y=84、42×42；文字 x=156、y≈88 |
| 右上章节标识 | x=1344 右对齐，y≈92 |
| 内页标题 | x=96、y=204；常用两行 |
| 两行标题后的副标题 | y≈452；单行标题可用 y≈346 |
| 正文区域 | 通常 y=548–1465；依版式调整 |
| 重点结论区域 | 通常 y=1480–1678 |
| 来源与必要限定 | x=96、y=1718，最多两行 |
| 页脚分隔线 | x=96–1344、y=1798，2 px |
| 页脚 | 左 y≈1820 放主题／日期；右 y≈1816 放 01 / 09 |
| 常用卡片圆角 | 28–32 px；封面主视觉 36 px |
| 常用卡片内边距 | 30–44 px |

96 px 是主内容安全边距。封面主视觉可以有意延伸至 x=54、宽 1332 px；文字仍保持主网格。按总页数生成页码，不把“09”硬编码到新任务。

默认九页节奏为：深、浅、浅、深、浅、深、浅、浅、深。浅色页承载案例和图解，深色页承载主张、指标、时机与行动。6–8 页时保留深色封面和结尾，按内容插入 1–2 页深色转折。

## 3. 中文字体与文字层级

使用 Noto Sans CJK SC Regular 与 Bold。原型以 NotoCJK、NotoCJKBold 注册到 Canvas；新运行时先定位真实字体文件并检查可用性，不复制旧工作区的绝对路径。正文和英文使用同一字体系统；不要依赖系统随机回退。

| 层级 | 字号 | 行高／用途 |
|---|---|---|
| 封面第一、二行 | 109 px Bold | 行间位置约隔 143 px |
| 封面主题行 | 122 px Bold | 荧光绿；按实际长度测宽 |
| 内页标题 | 88–96 px Bold | 110 px |
| 副标题 | 40–42 px Regular | 53–60 px |
| 卡片标题 | 40–58 px Bold | 随卡片尺寸，通常一行 |
| 正文／说明 | 38–42 px Regular | 55–66 px |
| 重点结论 | 45–49 px Bold | 60–64 px；长句可用 39 px、两行 |
| 标签 | 25–34 px | 圆角胶囊高 50–64 px |
| 来源与限定 | 23 px | 33 px |
| 页眉／页码 | 24–30 px | 页码 Bold |

只有来源、页眉、标签及“概念示意”一类辅助信息可以使用小字号；主要论证不得降为脚注。标题太长时先改文案或换行。每张卡片维持一个对齐轴，不为了空间随意混用居中和左对齐。

按真实字体逐行 measureText。中文可按字符换行；英文产品名与版本号优先保持完整 token。手动安排标题断行，避免括号、标点或英文单词被挤到孤立一行。关键名称同时在文案和成图中核对。

## 4. 可复用版式节奏

| 页型 | 原型尺寸与做法 | 适用内容 |
|---|---|---|
| 封面 | 三行大标题；下半部一张主视觉；底部短结论与标签 | 推荐主张 |
| 两张证据卡 | x=96、宽1248；两张纵向白卡；第一张约430高，第二张约376高 | 两个项目或事实信号 |
| 中心场景图 | 中心圆＋周围四张480×226卡；连接线先画、卡片后画 | 一个需求与四个场景 |
| 三条指标 | 深色页；三张1248×245横卡；左图标、右标题和说明 | 三个体验要求 |
| 机制＋两卡 | 上方1248宽机制卡；下方两张606宽卡、间距36 | 核心原理与两个条件 |
| 三条成熟信号 | 深色页；编号、标题、短说明、标签；行间细线 | 为什么现在 |
| 三步工程过程 | 三列388宽卡；列间约42；中间卡深色；短连接箭头 | 诊断、实现、验证 |
| 四项作品 | 2×2网格；卡606×422；间距36、行间30 | 四种个人成果 |
| 四步行动 | 深色页；左编号圆与纵线、右侧行动和结果 | 最小开始路径 |

每页选择一种主要版式。机制图和流程图直接用 Canvas 的矩形、圆、线、箭头和文字绘制，确保关系准确；概念性示意标注“概念示意”。图标采用统一线描，常用线宽4 px，尺寸64–94 px；不要引入一套不匹配的彩色贴纸。

重点结论常用1248×164卡，左侧6 px竖线，内文左起约66 px。深色结尾可用荧光绿底、深色文字。来源与页脚之间必须保持空隙。

## 5. 封面主视觉：生成插画，精确排文字

本方式只让图像生成工具创作无文字 hero 插画。封面标题、标签、来源、图标和其余八页由 Canvas 精确排版。它不是整页 AI 生图，也不是 HTML 页面截图。

主视觉默认用3:2横向构图，嵌入竖版封面的下半部。原型嵌入位置为 x=54、y=778、1332×888 px；下部还有一句结论，图像下沿需要留出低干扰区域。保留主要物体完整轮廓，避免强制拉伸；原始比例不同时先调整图框或等比适配。

可复用无字 hero 提示词，替换花括号字段后交给 imagegen：

    Use case: stylized-concept
    Asset type: text-free hero illustration for a Chinese technology editorial cover
    Primary subject: {one recognizable object that represents the learning topic}
    Supporting concept: {one abstract form that represents the benefit or mechanism}
    Style: refined 3D editorial product illustration, premium but restrained
    Scene: deep forest-green studio, dark seamless background
    Palette: near-black green #101B17, muted silver, restrained lime #BCED72 illumination
    Composition: landscape 3:2; one clear focal object and at most one supporting form;
      generous breathing room; preserve the complete silhouette;
      leave the lower band calm for later typography
    Lighting: soft controlled highlights, subtle contact shadow, selective green glow
    Constraints: no words, no letters, no numbers, no logo, no watermark,
      no UI text, no charts, no scientific labels, no dense background decoration

例如硬件主题可以用一台简洁设备和抽象芯片；软件方法可以用一个抽象结构和一条有节制的光路。按主题选择，不机械重复电脑或芯片。插画表达主题氛围，精确数据、架构和流程交给可控排版层。

生成后先检查物体、比例、色调、视觉重心和是否出现伪文字，再嵌入封面。新主题没有合适生成结果时继续修正主视觉；不要把临时占位图交付为完成稿。

## 6. 渲染与最少必要检查

使用 Node 的 @napi-rs/canvas 渲染整张卡片，用 sharp 导出发布图。依环境提供的 runtime 路径加载依赖。先注册字体，后测量文字，再绘制。生成过程中记录文本位置、字号、行数和溢出问题。

原型导出 PNG 为无损原图，JPG 使用 quality=96、chromaSubsampling=4:4:4。所有页面保持1440×1920。转换格式不改变内容、顺序、边界和尺寸。

只做能发现实际问题的检查：

1. 运行版面审计：文字不超过所属文本框和画布；页数、尺寸、文件编号正确。原型的 overflow 检查只覆盖宽度和画布边界，不能证明没有卡片重叠、断行错误或层级问题。
2. 生成总览：九页用3×3联系表；原型缩略图432×576、间距24、顶部132，整体1392×1956。检查明暗节奏、字号一致性、标题重复与信息密度。
3. 逐页打开最终成图：至少一次全尺寸检查每一页，重点看中文缺字、英文拼写、标题断行、脚注、箭头端点、图卡遮挡及底部安全区。
4. 看手机宽度效果：将单页按约360–432 px宽查看；读者应能立即认出主标题，并自然找到重点结论。正文太密时删改文案或拆分内容，不整体缩字。
5. 修复具体问题后，只重渲染并复查受影响的页面和总览。保留同一视觉系统，不因单页问题重做整套风格。

自动审计为0溢出后仍需视觉检查。不可只看源代码或只检查封面就宣布九页完成。

# 制作与交付

## 工作目录与依赖

使用一个新工作目录存放 `post.json`、`caption.txt`、`sources.txt`、当次 `hero.png` 和渲染结果。保持技能目录及其参考图只读。

默认渲染工具是 Node.js、`@napi-rs/canvas` 与 `sharp`。脚本优先正常解析模块，再尝试 `CODEX_PRIMARY_RUNTIME_NODE_MODULES`。用运行环境已有依赖；缺少时遵守环境许可，在当次工作目录安装依赖或用当前可用的精确排版工具，不覆盖系统环境。

寻找支持中文的字体时优先使用用户提供或环境已经安装的字体，例如 Noto Sans CJK SC、思源黑体。用 `rg --files` 查找 `.otf` / `.ttf`；必要时调用字体工具查看已安装字体。传入实际字体文件，确认粗体与常规体均加载成功。不要依赖旧会话路径，不从不明站点下载字体，不把字体许可文件漏掉后再分发字体。

渲染器的参数与各布局字段见 `renderer-schema.md`。修改示例中的主题、页眉、页脚、日期与文案后再用于真实任务；它只是无时效事实的排版示例。

## 生成封面素材

默认 hero 是 imagegen 生成的横向无字插画，再由 Canvas 放进封面。提示词、配色、留白要求见 `visual-system.md`。保留图像原文件；不要把 hero 原图当成最终封面交付。

封面生成结果已显示在对话中时，仍需把真正的最终封面和其余页收进 ZIP，因为用户要求的是发布文件包。按图像工具的文件输出方式取得实际路径，不编造路径或从缩略图反向重建原图。

只有用户请求修改已有插画时，按 imagegen 编辑规则先查看已有图，再传入参考路径。文案替换、页码修改与代码生成图的布局调整直接修改配置并重渲染。

## 打包命令

```bash
python3 /absolute/skill/scripts/pack_publish.py \
  --render-dir /absolute/work/rendered \
  --caption /absolute/work/caption.txt \
  --sources /absolute/work/sources.txt \
  --output /absolute/work/xiaohongshu_publish.zip
```

对明确要覆盖的当次包加 `--overwrite`；为新版本优先用新文件名。打包器读取并验证 JPG、PNG、总览和审计，不编辑图片。失败时修复具体问题后重跑。

发布说明中的尺寸与图片数量必须来自实际输出。文件名用两位页码，图数超过 9 时仍保持顺序；默认配置为 9 页。不要声称规格是小红书唯一支持或官方最优值。

## 文案与来源文件

`caption.txt` 使用“标题 / 正文 / 标签”的可直接复制纯文本结构。用第一人称观点，不伪造测试、工作经历和结果。`sources.txt` 至少逐条列出关键事实、完整 URL、资料日期、核查日期及必要条件。没有需要外部验证的事实时也写明“本篇为方法建议，无外部数据主张”，不要伪造来源凑数。

内部核查记录、layout audit、渲染配置与源代码保存到工作目录，不默认塞进发布包。

## 视觉验收与常见失败

| 症状 | 处理 |
| --- | --- |
| 标题或英文长词越界 | 缩短表述、显式换行、换布局；不压扁字形 |
| 正文字太密 | 合并同义句、减少支撑点或增加一页；不缩成脚注 |
| 中文缺字 | 使用真正支持中文的字体，重新渲染并查看 |
| 总览看不清字 | 总览用于检查节奏；另看逐页图片与手机宽度效果 |
| 图片好看但技术关系错 | 回到来源确认关系，用确定性图形重画 |
| AI 封面出现乱码或标识 | 用 imagegen 修正原插画，保留排版文字在 Canvas 层 |
| 旧输出混入新包 | 用新的输出目录，按当次审计列出的文件打包 |
| 个别案例查不到 | 去掉这个非必要案例，或说明关键证据缺口；不补造事实 |

自动检查通过后仍应看每一页。确认足够后停止额外验证，保存并交付可下载文件。
